# @mettascript/edsl
Write MeTTa *as TypeScript*. **An array in term position IS an expression** — `[parent,Tom,Bob]` is `(parent Tom Bob)` — so a program is data you build with `Array.prototype`. Also: combinator builders, a tagged template, typed relations, a fluent chain, and the space as a collection. Thin layer over `hyperon`: every builder makes an ordinary atom, so full MeTTa semantics (rewriting, nondeterminism, matching, types). Examples executed by tests.
**Pick** write MeTTa *from TS* with types→here · raw source→`core` · atom classes→`hyperon`. `npm i @mettascript/edsl`
**Core surface** `names("a","b")`/`vars("a","b")` spell names as literals (needed for schema typing); bare `names()`/`vars()` still mint any key, loosely typed; `sym("&limit")` is the single-name form, for one that cannot be destructured. Nesting is free; `val([1,2,3])` keeps an array a VALUE (MeTTa has no array type — `(1 2 3)` is an expression, so this is miniMAL's quote).
```ts
import { mettaDB, names, vars, val, M, If, gt, mul, sub, m } from "@mettascript/edsl";
const db = mettaDB(), { parent, fact, Tom, Bob } = names("parent","fact","Tom","Bob"), { x, y, z } = vars("x","y","z");
db.add([parent,Tom,Bob]);                       // (parent Tom Bob)   ·  db.add(parent(Tom,Bob)) too
db.query([parent,Tom,y]);                       // [{y:"Bob"}]  match &self over STORED atoms
db.query([[parent,Tom,y],[parent,y,z]]);        // join: all-pattern array = conjunction  ·  eval REWRITES
db.fn("balance-of", (a:{balance:number}) => a.balance);   // TS→MeTTa · db.call.fact(5) · db.import("fact")(6)
db.evalJs(m`(balance-of ${{balance:100}})`);    // [100]  ·  m`…` is the real parser, ${v} auto-grounds
```
**Typed patterns** A relation puts column types in one place; a schema does the same for source strings and array patterns. A column that is itself a TUPLE declares a nested expression one level down. Everything is CHECKED: wrong arity, a ground argument the column cannot hold, and a variable standing in two disagreeing columns are compile errors at any depth, each carrying its message (`QueryArityError`/`ColumnTypeError`/`VarConflictError`). `unknown` only where nothing declares the position — and the keys are still exact.
```ts
const Likes = rel<[person:string, drink:string]>("Likes"), Hot = rel<[roast:string]>("Hot");
const Serves = rel<[cafe:string, drink:[roast:string]]>("Serves");        // nested shape, needs no name
db.query(Likes("Ada", drink));            // {drink:string}[]   ·  Likes("Ada",42) is a compile error
db.query(Serves("Blue", Hot(drink)));     // {drink:string}[]   ·  Serves("Blue",["dark"]) is an error
db.query([Likes("A",who), Age(who,yrs)]); // {who:string; yrs:number}[]   join carries every column
const d2 = mettaDB<{relations:{Likes:[string,string]; Age:[string,number]}}>();
d2.q('(Likes "Ada" $drink)');              // {drink:string}[]  ·  q() parses the source AT THE TYPE LEVEL
d2.query([Likes_,"Ada",drink]);            // same checks on an array pattern  ·  d2.q('(Likes "Ada")') errors
```
**Defining functions** two ways, both handing back the ATOM so nothing is spelled twice. `db.define(name, (self, …vars) => body)` defines one in MeTTa — body-first `self` makes recursion work without a dead zone, arity comes from the callback's own parameter list, and `db.define<(n:number)=>number>` types it without a schema. `db.grounded(name, fn)` defines one in TypeScript. Several clauses = nondeterminism, so "otherwise" is a guard in the body, NOT a second literal-head rule (both would match). Well-known symbols are exported: `Self` (`&self`) · `True`/`False` · the metatypes · `NumberType`/`StringType`/`BoolType`/`AtomType`/`TypeType`/`Undefined`.
**Chain + grounded functions** two views of one idea. `db.grounded(name, fn)` makes a TS function BE an atom: applied+evaluated it runs, bare it is its symbol, so it stores, matches and quotes as data — MeTTa's own rule, and its signature is the contract (`double("no")` is a compile error, `db.evalJs(double(21))` is `number[]`). `M(x)` gives MeTTa's list stdlib the names `Array.prototype` has AND its typing: each step re-types the chain, so callbacks need no annotation and `.js(db)` is typed. `.map/.filter/.reduce/.forEach` take a PLAIN TS function (private token, body never enters the space); `.mapAtom/.filterAtom/.foldAtom` take a MeTTa template; `.pipe(fn)` puts a grounded function in with its type. Also `.size .at .head .tail .cons .min .max .try .catch .unify .match .collapse .superpose .quote .sealed .type .metatype .cast .unique .union .intersect .subtract`; any OTHER name becomes `(name self …args)`. Terminals `.run/.js/.runAsync/.jsAsync/.runOrThrow/.jsOrThrow(db)` · `.atom(db)` needs the runner when TS bodies are pending, and refuses rather than leaking private tokens.
```ts
const fact = db.define<(n:number)=>number>("fact", (self,n) => If(gt(n,0), mul(n,self(sub(n,1))), 1));
db.evalJs(fact(5));                             // [120], number[]  ·  fact("no") is a compile error
const double = db.grounded("double", (n:number) => n*2);   // db.evalJs(double(21)) → [42], number[]
M([1,2,3,4]).map(x => x*10).filter(x => x>15).reduce((a,x) => a+x, 0).js(db);   // [90], number[]
M(21).pipe(double).js(db);                      // [42]   ·  M([1,2,3]).mapAtom(v => mul(v,10))  MeTTa body
await M([1,2]).map(async x => x*100).jsAsync(db);   // [[100,200]]  ·  M(x)["my-op"](1) for hyphens
```
**Space as a collection** `db.space` has `size`, `add`, `delete`, `deleteAll`, `has`, `clear`, iteration, and the array methods over plain TS functions. `deleteAll(atoms)` is NOT a loop over `delete`: removing from `&self` rebuilds the interpreter's derived indexes, so one at a time pays that per atom (50 of 10k: 358ms vs 7ms). `of(Likes)`→that relation's facts as tuples typed from the schema, ready to go straight back in (`db.add([Likes,...row])`); `byHead()`→`Map<head, Atom[]>`; `toJS()`→nested arrays. It reads atoms AS STORED, where `(get-atoms sp)` reduces them. `db.useSpace(name, backend)` serves a NAMED space from a `Space` implementation instead of the interpreter's store — `new PersistentSpace()` gives one whose versions are values (`snapshot`/`restore` are pointer moves, `fork` shares structure), and a remote atomspace plugs in the same way. `&self` cannot be served this way, being the KB and the World read as one.
**Transactions and the change log** `db.transaction(tx => …)` commits the whole body or none of it: a throw restores the space and rethrows. `db.dryRun(tx => …)` runs it, reports, and restores either way — DataScript's `with`, for asking what a batch WOULD do. Both answer a report (`value`, `changes`, `before`, `after`, `committed`), DataScript's `:tx-data` over atoms; `db.undo(report)` goes back to `report.before`. `db.onChange(fn)` reports every write with no transaction involved, returning a stop function — each change is `{op, space, atom}`, the MeTTa debugger's `SpaceChangedEvent` shape, and `formatChanges` renders it. Changes are RECORDED as they happen, not computed by comparing before and after: comparing was linear in the SPACE (34.5ms to find one insertion among 100k), recording costs what it contains, and it reaches a remote space that has no before to hold. Rollback still SNAPSHOTS, which catches an `add-atom` MeTTa performed mid-evaluation and keeps atom order that a replay would not. What comes back is the SPACE — a file a grounded function wrote, a `bind!` token, a registered op are not atoms and do not.
**Stdlib** the whole library is exported as builders: spaces (`addAtom addReduct addAtoms addReducts removeAtom getAtoms newSpace`), lists (`mapAtom filterAtom foldlAtom forEachInAtom ifDeconsExpr sizeAtom indexAtom`), control (`If Case Switch Let LetStar Chain Eval Function Return Match All Superpose Collapse CollapseBind SuperposeBind Unify Sealed Quote Capture NoEval Id`), types (`getType getMetatype typeCast isFunction matchTypes`), state (`newState changeState getState`), errors (`ErrorAtom IfError returnOnError`), the assert family, maths (`pow sqrt abs log floor ceil round sin cos tan minAtom maxAtom randomInt xor`), text (`parseAtom repr stringToChars charsToString formatArgs`), modules (`bind pragma importModule registerModule gitModule trace getDoc help`).
**Schema** `mettaDB<{fact:(n:number)=>number}>()` types `db.call.fact(5)`, `db.evalJs(fact(5))`, `db.import("fact")`, and CHECKS `db.fn` and `db.rule(fact(x),…)`. Split form `{functions:{…}, relations:{…}}` keeps relation names off `call`/`fn`. No schema → permissive. Results are `unknown` (runtime rewriting), so `db.evalAs(atom, schema)` decodes with any **Standard Schema** — Zod/Valibot/ArkType/TypeBox/Yup — with no runtime dependency.
**Errors are VALUES** `(* "no" 2)` does not throw, it reduces to `(Error (* "no" 2) (BadArgType 1 Number String))`, which arrives in the ordinary results and reads as a successful answer to anything counting them. `isErrorAtom(a)` · `errorText(a)` · `errorAtoms(results)` see one; `db.evalOrThrow` / `db.evalJsOrThrow` / `db.evalAsyncOrThrow` / `chain.runOrThrow(db)` / `chain.jsOrThrow(db)` raise a `MettaError` instead, which carries `.errors` so MeTTa's own handling stays open. An unreduced expression is NOT an error. `Try(body, e => …)`/`Catch(body, fallback)` catch one: `if-error` alone CANNOT, since its `Atom` parameter means it inspects the argument unevaluated. A TS `throw` inside a grounded fn already arrives as `(Error …)`, so the round trip closes.
**Taking a result apart** `matchAtom(a).with(pattern, handler).otherwise(fallback)` (or `.run()`→`T|undefined`), ts-pattern's shape over ATOMS. The handler's argument is typed from the pattern and an unbound name does not compile. `P._` wildcard · `P.any/str/num/bool/sym/var/expr(name?)` guard, and bind when named · `P.when(pred,name?)` a predicate the shape checks cannot express · `P.union([…],name?)`/`P.not(pat,name?)` · `P.rest(name)` the remaining arguments · a bare literal compares by the atom it grounds to · nested arrays match nested expressions. `.withAny([p1,p2], h)` runs one handler off several whole shapes; `.returnType<T>()` fixes every arm's result. `isMatching(pat,a)`→boolean and `matchBindings(pat,a)`→binds-or-`undefined` for filtering rather than branching. It matches ATOMS rather than `atomToJs` output on purpose: unwrapping makes a symbol and a grounded string both a JS string, and that difference is the commonest MeTTa bug. `db.match(a)` is the same matcher with the schema's declared heads as its universe, so `.exhaustive()` insists every one has an arm: leave one out and `.exhaustive` types as `NonExhaustive<"Age">`, which has no call signature. ts-pattern takes its universe from a discriminated union; atoms have none, so the DECLARATION supplies it. Only a `names()` symbol in head position counts as covering a head — the arm for everything else is `.otherwise()` — and an atom from outside the declaration still reaches a `NonExhaustiveError` throw, which no static check can rule out.
```ts
matchAtom(a).with([Likes, P.str("who"), P.str("drink")], ({who,drink}) => `${who} likes ${drink}`)
            .with([Age, P.str("who"), P.num("years")], ({who,years}) => `${who} is ${years}`)
            .otherwise(() => "no idea");                // handler args typed: string, string / string, number
db.match(a).with([Likes,P._,P._], () => "l").with([Age,P._,P._], () => "a").exhaustive();  // both or it fails
```
**Why nothing matched** `db.why(pattern)`→structured, `db.explain(pattern)`→a line to print. Compares the pattern against what is STORED and names the first differing argument, calling out a METATYPE difference specifically: `(Likes Ada $d) matched nothing: you passed Symbol Ada and the space holds Grounded "Ada", which never match`. The HEAD case is called out the same way and needs no space to diagnose, since MeTTa matches functors and fires rules by SYMBOL head: `("get-atoms" "&self")` reports `the head is Grounded "get-atoms", not a Symbol, so nothing matches it and no rule fires`. A trace cannot say this — `@mettascript/debug`'s `explainCall` reports one reduction and no results — so bridge to it with `db.source()` when you want the evaluator's side too.
**Live queries** `const stop = db.watch(pattern, rows => …)` fires immediately, then whenever those ROWS change — including a MeTTa-level `add-atom` performed during an evaluation. An unrelated write does not wake it (rows are compared, not a dirty flag). `stop()` unsubscribes.
**Telling MeTTa the schema** a TS schema is erased, so `(get-type Likes)` is `%Undefined%` and `type-check auto` has nothing to enforce — which leaves every atom TS cannot see (from `run`, `import!`, a runtime `add-atom`, a decoded payload) unchecked. `db.declareRelations({Likes:["String","String"]}).typeCheck()` emits `(: Likes (-> String String Type))` and turns checking on, giving `(Error … (BadArgType 2 String Number))` / `IncorrectNumberOfArguments`. Opt-in and two separate calls: declaring is safe, enforcing rejects programs that used to run.
**Traps** *`query` doesn't run rules, `eval` doesn't read data* — the wrong one gives `[]` or the expression back. · *A JS string grounds to a grounded STRING, in HEAD position too* — `Likes("Ada","Coffee")` is `(Likes "Ada" "Coffee")` while `names().Ada` is the symbol `Ada`; they never match, so a source query must quote it too. Pick one spelling per program, and write a head that is not an identifier as `sym("get-atoms")` — `["get-atoms",x]` is the expression `("get-atoms" $x)`, which never reduces. · *An all-expression array is read as a conjunction* — spell `((f x) (g y))` with `e(...)`, which has no second reading. · *Destructure `names()`/`vars()` once and reuse* — each call mints a fresh proxy. · *A capitalized builder is a MeTTa form, not JS control flow* — `If(c,a,b)` builds an atom, both branches constructed. · *`db.call.x(...)` always returns an array*; `db.import` returns first-or-`undefined`.
**Modules** `mettaModule()` records what to add and carries its TYPE, so a fragment is a value you pass around rather than a file you `import!`. `.grounded/.asyncGrounded/.define/.relation/.atoms/.source`, then `.use(other)` merges two — tRPC's router merge, and it composes before any runner exists. `db.use(m)` applies it and the runner's schema gains everything it declared; using the same module twice is a no-op, since twice-added rules would answer twice. A signature is a VALUE (`["Number"],"Number"`) rather than a type argument, because TypeScript cannot infer one type argument while you supply another, and because the same list emits `(: quad (-> Number Number))` — which a TS type can never reach the engine. `m.declarations()` hands those over; nothing is emitted until you ask, for the same reason `declareRelations` is opt-in. `.source(src)` carries raw MeTTa — a module IS a file in MeTTa, and its `!`-queries are the only way `pragma!`/`bind!` reach one — and `.declare(name,args,ret)` types what that source already defines, since `define` would add a SECOND clause and MeTTa would answer twice. `db.callAsync.f(x)` is `call`'s awaiting form, needed whenever an `asyncGrounded` function is on the path.
```ts
const arith = mettaModule().define("quad", ["Number"], "Number", (self,n) => mul(n,4));
const data  = mettaModule().relation("Likes",["String","String"]).atoms([Likes,"Ada","Coffee"]);
const db2 = mettaDB().use(arith.use(data));     // .use merges modules; db2.use applies one, once
db2.call.quad(3);                     // [12], number[]   ·  db2.query([Likes,"Ada",drink]) → {drink:string}[]
```
